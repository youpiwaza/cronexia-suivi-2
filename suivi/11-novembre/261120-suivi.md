## Tests — GTA-1744 / workflows events en heures

Périmètre : relations + seeds + CRUD GraphQL, puis fonctions complexes du workflow `eventByDay` (création, mise à jour de brouillon, soumission, annulation, validation, refus, plafond RC). Requêtes prêtes à copier dans les fichiers `_tests_all_queries` de `workflow-resources`, `resources`, `user-profile-instances` et `event-by-days`.

Prérequis : migration `workflow_event_by_day` appliquée, `prisma generate`, seed dev après reset BDD, API Nest redémarrée (cycle `forwardRef` entre `EventByDaysModule` et `WorkflowResourcesModule`).

### 1. Templates

- [ ] `workflow(code: "seed_workflow_event_dep")` : `type` = `eventByDay`, `labelShort` = `Déplacement`, un seul niveau rang 1 rôle manager, `targetEventForTypeEventByDay.code` = `DEP`.
- [ ] `workflow(code: "seed_workflow_event_rc")` : même forme, `labelShort` = `Repos compensateur`, event cible `RC`.
- [ ] `workflow(code: "seed_workflow_event_cp")` : `type` = `eventRangeOnResource`, `targetEventForTypeEventByDay` est `null`. Le champ horaire ne remplace pas la cible en jours.
